# Laravel 9 -> 10

**PHP floor: 8.1** and **Composer 2.2+**. Both are hard gates. Bump PHP to 8.1 under Laravel 9 first.

This hop is calmer than 8 -> 9. The dependency churn already happened. The one real code break is small and mechanical.

## The runtime bites

- **`dispatchNow()` and `dispatch_now()` are removed.** Deprecated in 9, gone in 10. Replace with `Bus::dispatchSync()` and `dispatch_sync()`. This is the single most common break on this hop. Grep the whole app for `dispatchNow` and `dispatch_now`, including tests and jobs, because a missed one throws only when that job path runs.
- **Native type declarations everywhere in the skeleton.** Laravel 10 added argument and return types to skeleton methods and generator stubs. This is backwards compatible, but if you extend framework classes and override methods, your signatures may now clash with the parent's stricter types. PHP will fatal on an incompatible override. Check custom middleware, custom exception handlers, and anything overriding a framework method.
- **`doctrine/dbal` shifts.** Some column-change migrations that leaned on dbal behave differently; if you do `->change()` on columns, test those migrations against a fresh database.

## Not a break, but worth adopting

The **Process facade** arrived in 10 (`Illuminate\Support\Facades\Process`) for running CLI commands with a clean testable API. If you shell out with `exec()` or `Symfony\Process` directly, this is a nice later refactor, not part of the upgrade.

## Checklist

- [ ] PHP 8.1 + Composer 2.2 confirmed
- [ ] Every `dispatchNow` / `dispatch_now` replaced with the `Sync` variant (grep app + tests)
- [ ] Custom overrides of framework methods checked for signature clashes against the new native types
- [ ] `->change()` migrations tested on a fresh DB
- [ ] Suite green on staging

Official rename list: `laravel.com/docs/10.x/upgrade`.
