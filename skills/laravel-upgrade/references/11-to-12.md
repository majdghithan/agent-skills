# Laravel 11 -> 12

**PHP floor: 8.2** (unchanged from 11, no PHP bump needed for this hop).

Laravel 12 is a deliberate maintenance release, minimal breaking changes, most apps upgrade with little or no code change. The value of this file is the three things that DO bite, because they are quiet.

## The runtime bites

- **Carbon 3 is forced, Carbon 2 support is removed.** This is the real one. Every date and time in the app now runs Carbon 3, which is stricter about types and changed some formatting and diff behavior. If you do heavy date math, custom Carbon macros, or rely on specific `diffForHumans` / format output, test those paths hard. A package still pinned to Carbon 2 will block `composer update`, upgrade or replace it.
- **`HasUuids` now generates UUIDv7 by default.** UUIDv7 is time-ordered (better for indexing), but if any code, external system, or stored data assumes the v4 random format, new rows will not match the old shape. To keep v4 behavior, add `use Illuminate\Database\Eloquent\Concerns\HasVersion4Uuids as HasUuids;` on the affected models BEFORE upgrading. Silent data-shape drift otherwise.
- **Image validation no longer accepts SVG by default.** The `image` validation rule stopped allowing SVGs. Any upload form that accepted SVG now rejects it with no code change on your side. Opt back in explicitly with `image:allow_svg` (string rule) or `File::image(allowSvg: true)` (fluent rule). Bites avatar/logo uploads especially.

## Not a break

The new starter kits (React/Vue/Svelte on Inertia 2 + shadcn, Livewire on Flux + Volt) are for fresh installs. They do not touch an upgrade.

## Checklist

- [ ] Carbon 3 compatibility of your date code and every date-touching package confirmed
- [ ] `HasVersion4Uuids` added to models that must keep v4 (before upgrading)
- [ ] SVG-accepting upload rules updated to `allow_svg` if you support SVG
- [ ] `composer update` conflicts (usually a Carbon-2-pinned package) resolved
- [ ] Suite green, date-heavy and upload flows exercised

Official rename list: `laravel.com/docs/12.x/upgrade`.
